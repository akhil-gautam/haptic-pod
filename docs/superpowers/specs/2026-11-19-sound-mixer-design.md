# Sounds: a built-in ambient mixer for relaxation, meditation and sleep

Date: 2026-11-19 · Status: draft for approval

## Intent

Haptic Pod should ship with at least 20 relaxation, meditation and sleep sounds that are there on a
fresh install, with no import, account or network. You layer them into a mix (rain + fire + a
singing bowl), set each one's level with the click wheel, and let a sleep timer fade everything
out. It should feel like the rest of the app: wheel-driven, tactile, quiet and polished.

## Goals

- 24 sounds built in: 19 recordings plus 5 generated in code (see Catalogue).
- Layer up to 6 sounds at once, each with its own level.
- Per-sound level set with the wheel.
- Sleep timer: OFF / 15 / 30 / 45 / 60 / 90 min, with a 30 s fade-out at the end.
- Plays over your music, and in the background with the screen locked.
- The last mix (which sounds, at what level) is remembered across launches.
- Every bundled file is CC0 (public domain) and credited in the repo.

## Non-goals

- Downloading or streaming more sounds.
- Using imported music files as mixer sounds.
- Named, saved presets. A later add-on could build on the stored mix.
- Per-sound EQ, panning or effects.

## Anti-goals (failure even if it "works")

- An audible click, gap or level jump where a loop wraps.
- The music EQ, reverb or ambience colouring the sounds.
- Any file in the repo that isn't CC0, or any file without a recorded source.
- A mixer problem stopping or glitching the music.
- More than about 30 MB added to the app.
- Noticeable repetition: a bird call that clearly recurs every 20 s.

## Constraints

- Swift 6 strict concurrency, iOS 18, SwiftUI with the UIKit lifecycle, generated by xcodegen.
  `project.yml` must include the sound files as bundle resources.
- One `AVAudioSession` is shared with:
  - `PlayerService` (music), which sets `.playback` with no options when it starts.
  - `ClickSound`, which may switch to `.mixWithOthers` while idle if another app is playing.
- The wheel model is already crowded. Centre-press semantics must stay simple and match the Now
  Playing volume/scrub pattern.
- No test target exists. Verification happens on device with `-screen` debug launch arguments.

## Approaches

### Where the sounds come from

- **Freesound CC0 recordings plus generated noise (picked).**
  - Recordings: Freesound shows a licence per file. Each one is confirmed as CC0 on its own page
    and taken from the public high-quality preview (128 kbps MP3), so no account is needed.
  - Generated: noise and tones are made in code, so there are no files and no licence question.
- **Moodist's sound set (rejected).** It mixes CC0 and Pixabay-licence files without saying which
  is which. The Pixabay licence also forbids redistributing the files on their own, which a public
  repo does.
- **All generated (rejected).** Synthetic rain, birds and fire sound fake, and that defeats the
  point.

### How they play (you picked: separate engine)

- **A. Separate `AVAudioEngine`, recordings decoded into memory and looped (picked).**
  - Sample-accurate, gap-free loops.
  - Fully isolated from the music graph.
  - Cost: about 15–20 MB of memory per active recording (45–60 s stereo float).
- **B. Stream each file from disk (rejected).** It uses little memory, but compressed files tick
  at the loop point unless they ship uncompressed (about 5× the size) or use a custom ring-buffer
  reader.
- **C. Add nodes to the music engine (rejected).** It couples the mixer to EQ, reverb and track
  logic, and a mixer bug could stop the music.

## Design

### Catalogue

There are three kinds of sound:

- `.loop(file)`: a recording that loops forever.
- `.struck(file, every: ClosedRange<Double>)`: a single strike, such as a bowl, bell or gong.
  It is re-struck at random intervals within the range, at a slightly varied level, so it never
  becomes a metronome.
- `.generated(Generator)`: rendered live in an `AVAudioSourceNode`.

The list is ordered by group. The group name is shown in the title bar for the selected row,
e.g. `SOUNDS · RAIN`, so there are no header rows and the wheel never has to skip one.

| Group | Sound | Kind |
|---|---|---|
| RAIN | LIGHT RAIN, HEAVY RAIN, RAIN ON ROOF, THUNDERSTORM | loop |
| WATER | OCEAN, STREAM, WATERFALL | loop |
| NATURE | FOREST BIRDS, WIND IN TREES, OPEN FIELD | loop |
| NIGHT | CRICKETS, FROGS, NIGHT FOREST | loop |
| FIRE | CAMPFIRE | loop |
| MEDITATE | SINGING BOWL, TEMPLE GONG | struck |
| MEDITATE | WIND CHIMES, WATER FOUNTAIN | loop |
| INDOOR | AIRPLANE CABIN | loop |
| NOISE | WHITE NOISE, PINK NOISE, BROWN NOISE | generated |
| TONES | DEEP DRONE, THETA BEATS (binaural, labelled "headphones") | generated |

The exact Freesound recordings, with id, author, link and licence, are listed in
**Bundled recordings** below. Downloading them is part of approving this doc.

### Asset preparation (offline, committed script)

- `scripts/prepare-sounds.sh` (bash, ffmpeg) runs these steps:
  1. Download each listed HQ preview into a scratch folder. Raw downloads are never committed.
  2. Trim to a clean 50 s window for loops (75 s for FOREST BIRDS), or the full ring-out, up to
     20 s, for strikes.
  3. Make loops seamless by crossfading the last 3 s into the start.
  4. Loudness-match everything (EBU R128, about −24 LUFS), so a mix starts balanced at 50%.
  5. Encode AAC-LC 128 kbps, 44.1 kHz stereo `.m4a` into `HapticPod/Resources/Sounds/<id>.m4a`.
- `HapticPod/Resources/Sounds/CREDITS.md` lists title, author, Freesound URL and "CC0 1.0" for each
  file. The README gets a short "Sounds" section linking to it.
- Expected size: about 0.8 MB per 50 s file, roughly 16–18 MB in total.
- An automated screen flags sudden events before anything is bundled:
  - ffmpeg loudness/peak stats per 1 s window.
  - A window more than 12 dB above the clip's median is reported, so a different window or the
    backup recording can be chosen.
  - This is no substitute for listening: the final check is by ear on the phone.

### Audio: `SoundMixer` (new, `HapticPod/Sounds/`)

- `@MainActor @Observable final class SoundMixer` owns its own `AVAudioEngine`.
- Each active sound is one channel:
  - Recordings use an `AVAudioPlayerNode`.
  - Generators use an `AVAudioSourceNode`.
  - Every channel connects to `mainMixerNode`.
  - The channel level is applied with a short ramp (about 50 ms), so wheel steps don't produce
    zipper noise.
- **Turning a sound on:**
  - The file is decoded into an `AVAudioPCMBuffer` off the main actor.
  - It is scheduled with `.loops`.
  - It fades in over 1.5 s.
  - Turning it off fades out over 1 s, then detaches the node and frees the buffer.
- **Struck sounds:**
  - The strike buffer is scheduled again at random intervals.
  - The first strike plays immediately, so turning one on gives instant feedback.
- **Generators**, all with float state held in the render block:
  - White noise.
  - Pink noise (Paul Kellet filter).
  - Brown noise (leaky integrator).
  - Deep drone: three detuned sines around 55, 110 and 165 Hz with a slow 0.05 Hz swell.
  - Theta beats: 200 Hz left, 206 Hz right, under a soft pink bed.
- **Session** *(builder call)*: starting the mix follows `ClickSound`'s rule.
  - If another app (Spotify, Podcasts) is already playing, the mix joins it with `.mixWithOthers`,
    so sleep sounds can sit under a podcast. The lock screen keeps showing the other app.
  - Otherwise it activates `.playback` with no options, the same as our music, and owns the lock
    screen.
  - Our own music and the mix always play together.
- **Interruptions:**
  - A call or an alarm pauses the mix. It resumes when iOS says `shouldResume`.
  - Unplugging headphones pauses the mix.
  - An engine configuration change (AirPods connecting) restarts the engine and reschedules every
    active channel.
- **Limits:**
  - *(builder call)* Up to **6** active sounds. Turning on a seventh is refused with the `.thud`
    haptic and a brief "MAX 6" on the row.
  - Loops are 50 s (about 17.6 MB each as stereo float), so the worst case is about 106 MB of
    decoded audio. FOREST BIRDS may use 75 s.
  - Generated sounds cost no memory, but they count toward the 6 to keep the rule simple.
- **Persistence:**
  - `UserDefaults` key `soundMix` stores `[soundID: level]`.
  - The saved mix is restored on launch, but paused. It never auto-plays on launch.

### Sleep timer

- The SLEEP TIMER row cycles OFF → 15 → 30 → 45 → 60 → 90 → OFF.
- While it is running, the row shows the remaining time (`23:41`).
- In the last 30 s it fades the mix out, and it fades the music out too if music is playing.
- When it ends, it pauses both and restores their levels for next time.
- *(builder call)* It is its own small `SleepTimer` object, separate from the mix, and it works on
  whatever is playing.
  - Set it while only music plays, and it fades and pauses the music.
  - It keeps counting while any audio plays, which keeps the app alive in the background.
  - If nothing is playing when it fires, it just turns off.
  - The music fade uses the music engine's output volume, not system volume.

### Lock screen and remote controls

*(builder call)* One shared **owner**, music or mix, gets the controls: whichever the user started
or resumed most recently. Pausing doesn't change the owner, so lock-screen Play resumes what you
just paused.

- **Owner is music:** music owns Now Playing info and the controls, as it does today.
- **Both playing:** lock-screen Pause pauses both, and the following Play resumes both.
- **Wheel's bottom play/pause zone:**
  - On the SOUNDS screen, it toggles the mix.
  - Elsewhere, it toggles the music, or the mix if no song is loaded.
- **Owner is the mix:**
  - Now Playing shows "Sounds", with the active sound names as the subtitle, e.g.
    "Rain · Campfire · Bowl".
  - Play/pause/toggle control the mix.
  - Next/previous are disabled.
- The routing lives in one place: `PlayerService.handle` asks the owner before acting.

### Screen and wheel

- The home menu gets **SOUNDS** between SHUFFLE SONGS and EXTRAS.
- A new `Screen.sounds` uses a `ListContent.sounds` list with three control rows and then the 24
  sounds:

```
 SOUNDS · RAIN                         ▮▮▮
 ─────────────────────────────────────────
 ▶ PLAY MIX                        3 ON
   SLEEP TIMER                    30 MIN
   CLEAR MIX
   LIGHT RAIN                ▬▬▬▬▬▭▭▭
 ▌ HEAVY RAIN                ▬▬▬▬▭▭▭▭  ◀ selected
   RAIN ON ROOF
   THUNDERSTORM              ▬▬▭▭▭▭▭▭
```

- **Rows:**
  - A sound that's on shows a thin level bar on its right; a sound that's off shows nothing.
  - PLAY MIX becomes PAUSE MIX while the mix is playing. Its value is the number of active sounds.
- **Centre press:**
  - On an off sound: turns it on at 50%. If the mix was paused, the mix starts.
  - On an on sound: enters **adjust**. The row highlights and the bar shows the percentage.
  - On PLAY/PAUSE: toggles the mix.
  - On SLEEP TIMER: cycles the timer.
  - On CLEAR MIX: fades all sounds out and switches them off.
- **In adjust:**
  - The wheel changes that sound's level in 1/32 steps, with a tick per step and a firmer bump at
    100%.
  - Turning it to 0 switches the sound off and leaves adjust.
  - A centre press, MENU, or 4 s idle leaves adjust. This matches scrub mode on Now Playing.
- **Haptics:** reuse the existing kinds:
  - `.click` when a sound comes on.
  - `.tick` for level steps.
  - `.home` for the 100% stop.
  - `.thud` for MAX 8.
- `-screen sounds` is added to the debug launch map.

## Left to the builder

- Exact view styling within the existing `SettingRow` and `WindowedList` look.
- How to ramp channel levels (per-channel `AVAudioMixerNode` or player volume stepping).
- File and type names beyond those named here.
- The `project.yml` resource mechanism (folder reference or file group).
- The loop crossfade technique in ffmpeg, as long as the result is seamless when checked by ear
  at the wrap.
